# 아파트 입지·가격 분석기 v0.8.3

첨부된 `location-analyzer-v0.8.2.zip`을 이어서 수정한 로컬 실행본입니다. 분석 엔진 버전은 0.3.0입니다.

## 로컬 실행

Node.js 22.13 이상 22.x에서 압축을 푼 뒤 `package.json`이 있는 폴더에서 실행합니다.

```sh
npm ci
npm run dev
```

브라우저에서 `http://localhost:5174/app`을 엽니다. 키가 없는 환경에서는 ‘가상 데모’에서 관측을 확인하거나, 주소로 시작해 사건·거래를 직접 입력할 수 있습니다. 독립 앱의 기본 실행에서 협의체 시동 수신은 비활성입니다.

## 사건 전후 비교 읽기

1. **대상·입지 사건**에서 주소·전용면적·분석 기준일을 입력합니다. 사건에 근거 문서와 일정을 연결하고, 공개일과 실제 발생일을 구분해 기록합니다.
2. **비교단지·실거래**에서 사건이 처음 알려진 날 또는 선택 일정의 실제 발생일을 고릅니다. 공개일을 확인할 수 있는 자료만 분석에 사용합니다. 선택한 날짜를 중심으로 전후 3·6·12개월을 조회합니다. 기간은 시작일을 포함하고 종료일을 제외합니다. 사건 당일은 후행 기간에 들어갑니다.
3. 좌표가 확인된 단지에서 영향권과 비교군을 선택합니다. 영향권에는 본건 반경을 적용합니다. 대조지역은 같은 기간의 별도 비교군으로 지정할 수 있습니다. 선택 단지별로 본건 전용면적 허용범위와 동일한 5㎡ 구간을 전후에 적용합니다. 결과는 개별 거래 단가의 중위값이며 1전용평은 400/121㎡입니다. 가격 변동률은 반올림 전의 두 중위값으로 계산합니다.
4. **분석 결과 → 보고서·저장**으로 이동합니다. 입력 변경 후에는 기존 결과에 ‘재분석 필요’가 표시됩니다. 브라우저 저장 목록에서 다시 열고, 보고서의 ‘실행’에서 당시 입력과 근거를 선택할 수 있습니다.

공식 거래는 선택한 시군구·월에 대한 전 페이지 건수 대사가 필요합니다. 표본이 기간별 최소 건수에 못 미치거나, 관찰기간이 끝나지 않았거나, 공식 응답이 누락되면 전후 중위가격과 변동률을 보류합니다. CSV는 제공된 거래의 관측으로 표시합니다. CSV의 전체 시장 포괄 여부는 확인할 수 없습니다. 같은 조건으로 보이는 거래에 공식 ID가 없으면 복수 계약일 수 있어 기존의 묶음 건수·해제 건수 대사를 유지합니다.

## 실제 API 설정과 요청

서버 프로세스에만 `MOLIT_SERVICE_KEY`(공공데이터포털 일반 인증키의 디코딩 값), `KAKAO_REST_KEY`(카카오 로컬 REST 키)를 설정한 뒤 서버를 시작합니다. 서버가 국토부 키를 URL 쿼리로 인코딩합니다. 로컬 기본 수집 상한은 12개 달입니다. 사건 전후 각 6개월이나 12개월을 **일 단위**로 비교하면 경계 달을 포함해 13개 또는 25개 달이 필요할 수 있습니다. 로컬에서 수집 범위를 늘릴 경우 서버의 `PUBLIC_DATA_MAX_MONTHS`를 필요한 달 수로 설정합니다.

| 서버 요청 | 요청 항목 |
|---|---|
| 카카오 GET `https://dapi.kakao.com/v2/local/search/address.json` | `query`에 대상 주소 또는 단지 지번. 서버가 `Authorization: KakaoAK <REST_KEY>` 헤더를 설정 |
| 카카오 GET `https://dapi.kakao.com/v2/local/geo/coord2regioncode.json` | `x` 경도, `y` 위도. 중심과 반경 안 16개 지점의 시군구 확인 |
| 국토부 GET `https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade` | `serviceKey`, `LAWD_CD` 5자리, `DEAL_YMD` YYYYMM, `numOfRows`, `pageNo`. 시군구·월별로 페이지와 총건수 대사 |

국토부 매매 응답에 거래의 최초 공개일이 없는 경우 서버가 실제로 조회한 날짜를 사용합니다. 오늘 조회한 자료로 예전 기준일 당시 공개 여부를 입증할 수 없습니다. 그 시점의 출처가 있는 CSV는 `자료공개일` 열(YYYY-MM-DD)에 근거 날짜를 기재합니다. 이 열이 없는 새 CSV는 가져온 날을 사용합니다. 거래금액은 원 또는 만원 단위의 세대 총액입니다. `가격기준`을 기재할 때에는 `세대당`, `세대당 총액`, `household` 중 하나를 사용합니다.

## 로컬 검증

```sh
npx playwright install chromium
npm run test:all
```

이미 설치된 Chromium을 사용하면 실행 파일 경로를 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다. 전체 시험은 타입 검사, 로컬 빌드, 단위·통합 시험, 브라우저 시험 순서로 실행됩니다. Vercel 형식도 로컬 디렉터리로만 빌드합니다.

`tests/e2e/v083.test.ts`는 가상 사업지를 브라우저에 입력하고, 모의 카카오·국토부 HTTP 응답을 실제 서버 어댑터에 통과시켜 전후 가격·저장·재열기·보고서를 확인합니다. 재현할 때에는 먼저 `npm run build`를 실행한 뒤 아래 명령을 사용합니다. 실제 서비스 키는 필요하지 않습니다.

```sh
node --import tsx --test tests/e2e/v083.test.ts
```

# v0.8.1 — 입지 근거 문서 보존, 실행 번호별 보고서 재출력

- **입지 근거 문서**: 새 실행본의 [입지-NN] 인용에 그 사건에 연결된 근거 문서를 실행 시점 값으로 함께 보존한다(문서 제목·문서번호·발행기관·발행일·자료 기준일·확인일·페이지·절·확인한 사실·기록 수준·판단·근거 일정·기준일 이후 문서 여부). 근거 패널과 보고서 부록 G에 표시. 이후 근거를 고치거나 지워도 과거 실행의 문서 기록은 그대로. 원문 대조는 사용자 기록이며 앱이 자동 검증하지 않는다.
- **실행 번호별 보고서**: ④ ‘보고서·변경 이력’에서 실행 번호를 고르면 그 실행 당시의 제목·사업지명·주소·검토가격·조건·근거 목록·조회 기록과 그 실행 결과 수치로 요약·질문·초안을 다시 만든다(파일명에 run 번호, 상단에 ‘실행 #n 당시 기록 기준’). 새 실행본은 `result.reportContext`에 보고서 맥락을 보존한다.
- **당시 정보가 없으면 채우지 않음**: v0.8.1 이전 실행처럼 맥락이 남지 않은 실행은 사업지명·근거 목록·반경·거래 건수·조회 기록·문서 상세를 ‘당시 정보 미보존’으로 표시한다. 현재 작업본 값으로 채우지 않으며, 결과에 남은 주소·수치만 쓴다.
- **계산 불변**: 분석·관측 계산 코드 변경 없음. v0.7.2와 같은 가상 사례(데모·CSV, 3·6·12개월) 계산값·보고서 숫자 일치.

# v0.8.0 — 협의체 시안 계열 UI, 4단계 화면, 근거 열기·복귀, 실행본 인용 근거 보존

- **화면**: 딥 네이비 상단(분석 대상 요약: 주소·사업지명·전용면적·검토가격·분석 기준일, 없으면 ‘미입력’) + 밝은 작업 영역 + 플럼 선택 강조. 첫 화면은 주소 입력과 ‘분석 시작’이 중심이며, 시작하면 입력 카드가 위로 줄어들며 상단 요약으로 이어진다(‘동작 줄이기’ 설정이면 바로 이동).
- **4단계**: ① 대상·자료 → ② 입지·비교 조건 → ③ 분석 결과 → ④ 보고서·저장. 한 번에 한 단계만 보이고, 단계 버튼·이전/다음·브라우저 뒤로/앞으로로 이동해도 입력·선택은 기록에 남는다. 다시 열면 보던 단계로 돌아온다.

- **실행본 인용 근거 보존**: 새 실행본은 인용에 필요한 거래(대표 비교단지별 최근 최대 40건)·사건 일정·관측 사용 단지를 그 실행 시점 값으로 `result.citations`에 따로 보존한다. 이후 거래·사건 수정·삭제, 새로고침, JSON 복원 후에도 과거 실행의 인용은 바뀌지 않는다. 이전 버전 실행본은 ‘당시 근거 상세 미보존’으로 표시하고 현재 입력으로 다시 채우지 않는다. ④에서 실행별 인용을 다시 열 수 있고, 보고서 부록 G에 인용 목록을 남긴다.
- **계산 불변**: 분석·관측 계산 코드는 v0.7.2와 같다. 같은 가상 사례(데모·CSV, 3·6·12개월)로 수정 전후 계산값·보고서 숫자 일치 확인.

- 계산(analysis·tradeMerge·runs·importers·observeGroups 수치)은 v0.6.2와 같다. 같은 가상 자료로 3·6·12개월 중위·건수·변동률·%p 일치 확인.

# v0.7 — Vercel 배포(자동 조회 지원)

GitHub `main`에 올리면 Vercel이 `npm run build:vercel`(Build Output API)로 화면과 서버 함수를 함께 배포한다. 국토부·카카오 키는 **Vercel 환경변수에만** 넣고 저장소·빌드 결과·브라우저로 보내지 않는다.

| Vercel 환경변수 | 내용 |
|---|---|
| `MOLIT_SERVICE_KEY` | 공공데이터포털 ‘국토교통부_아파트 매매 실거래가’ 일반 인증키 |
| `KAKAO_REST_KEY` | 카카오디벨로퍼스 REST API 키(주소→좌표, 주변 시군구) |
| `KAKAO_JS_KEY` | (선택) 카카오 지도 JavaScript 키 — 카카오 콘솔에서 배포 도메인만 허용 |
| `APP_ACCESS_PASSWORD` | 자동 조회용 공용 접속 비밀번호 |
| `APP_SESSION_SECRET` | 로그인 쿠키 서명용 임의 문자열(32자 이상) |

- 자동 조회는 접속 비밀번호로 로그인한 사용자만 쓸 수 있다(서명 쿠키 12시간, CSRF 토큰, 같은 사이트 요청만, 인스턴스별 횟수 제한). 비밀번호·비밀값이 없으면 자동 조회를 막는다. 분석·저장·보고서는 로그인 없이 동작하며 저장은 각자 브라우저에만 된다.
- 함수: `/api/session`, `/api/login`, `/api/logout`, `/api/public-data/lookup`(최대 60초), `/launch`는 계속 대기(503).
- 서버 임시 분석 저장(협의체 자동 실행용)은 서버리스 배포에서 쓰지 않는다.
- 로컬 확인: `npm run build:vercel` 후 `tests/helpers/vercelLocal.ts`로 흉내 서버를 띄워 시험한다(`tests/e2e/vercel.test.ts`). 실제 Vercel 동작은 첫 배포에서 확인해야 한다.

# v0.6.3 — GitHub Pages 웹 버전

- **배포**: `main` 브랜치에 올리면 `.github/workflows/pages.yml`이 타입검사·빌드·단위/통합 시험 후 서버 없는 웹 버전(`dist/preview/index.html`)을 GitHub Pages에 올린다. 처음 한 번 저장소 Settings → Pages → Source를 **GitHub Actions**로 지정해야 한다. 비공개 저장소의 Pages는 GitHub 유료 요금제가 필요하고, Pages 주소 자체는 누구나 열 수 있다(Enterprise 제외).
- **API 키를 쓰지 않음**: 정적 페이지에 키를 넣으면 누구나 볼 수 있으므로 국토부·카카오 키를 등록하지 않는다. 자동 조회는 사용할 수 없고 주소·CSV·JSON 입력, 분석, 저장, 보고서만 동작한다. 저장은 각 사용자 브라우저에만 된다.
- **v0.6.2 대비 수정**: 그룹 관측과 무관한 입력만 바뀌면 ‘값이 다르다’ 대신 ‘다시 실행 필요’로 안내, 보고서 단지명이 겹치면 시군구·지번까지 붙여 구별, 단독 접속(Pages)에서는 내려받기·인쇄를 그대로 사용(다른 화면 안 미리보기일 때만 내용 패널·제한 표시).

## 사용 순서(독립 사용)

1. 첫 화면에 주소를 입력하고 **분석 시작**을 누릅니다. 전용면적·검토가격·준공(예정)연도·분양/준공 예정일은 ‘선택 입력’에서 필요할 때만 넣습니다.
2. 결과 1페이지: 요약 3블록(① 입지 변화 ② 가격 영향과 근거 ③ 주요 불확실성)과 대표 비교단지 표가 먼저 보입니다.
3. 자료 추가(접힌 상세 영역)
   - **실거래·비교단지 상세**: 실거래 CSV를 가져오거나, 키가 설정돼 있으면 ‘주소로 좌표·실거래 자동 조회’를 누릅니다. 단지별 거리·준공연도 확인값과 포함/제외 지정을 입력할 수 있습니다.
   - **입지 사건·근거 상세**: 사건과 일정 이력(발표일·적용일·수집일)·근거 문서·첨부를 기록합니다.
   - **입력·세부 설정**: 면적·검토가격·일정과, 접힌 ‘세부 설정’(반경·면적 범위·기간 등)을 고칩니다.
4. 입력을 바꾸면 **분석 다시 실행**을 누릅니다.
5. **이 브라우저에 저장** → 첫 화면 ‘저장한 분석’에서 다시 엽니다. JSON 내보내기·백업 복구도 가능합니다.
6. **보고서·변경 이력**에서 1페이지 요약+근거 부록, 확인 질문 초안, ‘~임.’ 문체 보고서 초안, 변경표를 Markdown·텍스트로 내려받거나 인쇄/PDF로 저장합니다.

예시 자료(모두 가상): `examples/sample-data/demo-nearby-trades.csv`, `examples/sample-data/demo-location-events.json`, 첫 화면의 ‘가상 데모로 사용해 보기’.

## 실거래 자료 처리

- **중복 제거**: 같은 CSV·API 자료를 여러 번, 다른 순서로 가져와도 같은 거래는 한 번만 집계합니다. 식별 기준은 ① 원천 거래 식별자(CSV의 `거래ID` 등, 있을 때) ② 없으면 단지 식별·전용면적·층·동·계약일·거래금액이 같은 ‘동조건 묶음’입니다. 국토부 아파트 매매 API에는 거래 단위 공식 식별자가 없어 ②를 씁니다.
- **원천 거래 ID는 출처 범위와 함께**(v0.5): ‘출처 A의 ID 1’과 ‘출처 B의 ID 1’은 다른 거래입니다(CSV `ID출처` 열). 같은 자료 안 같은 출처·ID·같은 내용은 1건만 보존, 내용이 다르면 둘 다 보존하고 ‘ID 충돌 확인 필요’(대표 통계 제외). 출처·ID가 같아도 단지명·시군구·법정동·단지코드가 다르면 병합하지 않습니다. 출처가 지정된 ID의 금액·면적·계약일·층·동·지번·준공연도 변경은 ‘원천 정정’으로 반영·기록하고, 출처 미지정 ID의 값 변경은 자동 반영하지 않고 보류합니다(해제만 새로 붙은 경우는 반영). 사용자 제외 사유·단지별 거리·준공연도 확인값(사용자 입력)은 원천 정정으로 바뀌지 않습니다. 이미 저장된 같은 ID 사본은 지우지 않고 ‘거래 진단’에 표시하며, 같은 내용 사본만 사용자가 정리할 수 있습니다(정리 전 작업본은 버전으로 자동 보관). 통계에서는 같은 내용 사본을 1건으로 계산합니다.
- **입력 순서를 식별자로 쓰지 않음**: 동조건 묶음 안의 거래는 기록된 정보로 서로 구별할 수 없으므로 묶음 단위로 건수와 해제 건수만 대사합니다. 새 자료의 묶음 건수가 더 많으면 차이만큼 추가하고, 적으면(부분 자료일 수 있음) 기존을 유지합니다. 해제는 되돌리지 않으며, 2건 이상 묶음에서 반영한 해제는 ‘어느 거래인지 특정 불가’로 표시합니다.
- **가격 차이로 자동 정정하지 않음**: 같은 조건에 금액만 다른 거래가 따로 들어오면 둘 다 보존하고 ‘별도 거래 또는 정정 여부 확인 필요’로 표시합니다(대표 표본에 포함되면 ‘표본 수·중위 단가 확정 아님’을 주요 불확실성에 표시). 같은 자료 안에 함께 들어온 경우는 원천이 두 거래를 함께 제공한 것이므로 별도 거래로 봅니다. 정정은 원천 거래 식별자가 같을 때만 처리합니다. v0.3에서 금액 차이로 자동 정정된 기록은 이력을 보존하고 확인 필요로 표시합니다.
- 가져올 때마다 신규·중복·해제 반영(특정 불가 건수)·원천 식별자 정정·별도 거래/정정 확인 필요·부분 자료 묶음 건수를 표시합니다(받은 건수 = 신규 + 중복 + 해제 반영 + 원천 식별자 정정).
- **수집 상태 3가지를 따로 표시**(공공 API): ① 거래 응답 수집·건수 대사 — 시군구·월별 응답의 전체 건수(totalCount)를 확인해 모든 페이지를 받고 수집 건수와 대사, 실패·불일치·페이지 상한이면 ‘일부만 수집’ ② 주변 행정구역 탐색 — 반경·반경의 1/2 위 8방위와 중심, 17개 표본 지점의 시군구를 확인. 표본 방식이라 ‘완료’ 상태가 없고 행정구역 경계 전체를 보장하지 않으며, 지점 실패·시군구 상한(6곳)이면 ‘일부’ ③ 단지 좌표 확인 — 확인 대상 중 좌표를 찾은 수, 상한(80곳). 각 상태가 대표 비교단지에 주는 영향을 함께 표시합니다.
- **협의체 자동 실행 경로**(대기 기능): 일반 자동 조회와 같은 수집·병합·입력 스냅샷 경로를 씁니다. 자동 조회 결과는 작업본에만 들어가고 최초 수신 사본은 받은 그대로 둡니다.
- **비교단지**: 거리가 확인된(좌표 또는 사용자 입력 거리) 반경 내 단지 중 가까운 순으로 최대 5개를 대표로 선정합니다. 좌표·거리를 확인하지 못한 단지는 ‘확인 필요 후보’로 따로 표시하고 대표 통계에 넣지 않습니다. 같은 이름의 단지는 단지코드 또는 시군구·법정동·지번으로 구분해 표시합니다.

## 입지 사건·근거

- 입지 뉴스·고시 **자동 수집 기능은 없습니다.** 모든 사건·근거는 사용자 입력이며 ‘사용자 입력’으로 표시합니다.
- 근거 기록 수준: ‘사용자 입력(출처 미기재)’ / ‘출처 기재(원문 대조 기록 없음)’ / ‘공식 원문 대조 기록(사용자 기록, 자동 검증 아님)’. 마지막 수준은 공공기관 원문·문서번호 또는 첨부·페이지·발행일·‘원문 직접 대조’ 표시가 모두 있어야 하며, 사용자가 ‘사실로 기록’만 한 것으로는 공식 확인으로 표시하지 않습니다.
- 분석 기준일 이후에 처음 알려진 사건·근거는 분석에서 빼고 목록으로 보여줍니다. 기준일 이전에 취소가 알려진 공급은 물량 집계에서 뺍니다(기준일 이후에 취소가 알려졌다면 기준일 시점에는 유효한 공급으로 봅니다).

## 결과와 입력의 관계

- 자동 조회·CSV 가져오기 응답은 응답 시점의 최신 작업본에 병합합니다(대기 중 바꾼 검토가격·제외 사유 등을 덮어쓰지 않음). 조회 이후 주소·기준일·반경·시군구·기간·본건 좌표가 바뀌면 이전 조건의 결과 적용을 보류하고 ‘그래도 적용/버리기’를 묻습니다. 더 최근 조회가 있으면 이전 응답은 적용하지 않습니다.
- 동조건 묶음에서 해제 대상을 특정할 수 없고 그 묶음에 사용자 제외가 섞여 있으면 유효 표본을 확정하지 않고 ‘유효 표본 a~b건’ 범위로 표시합니다(중위 단가 등은 확정 표본 기준).
- (v0.5.2) 해제 대상 특정 불가 표시는 매 병합 후 묶음의 현재 거래 수·해제 수로 다시 계산합니다. 묶음 거래가 모두 해제되면 표시를 지우고 ‘특정 불가 해소’ 이력을 남기며, 묶음이 커지면 새로 합류한 거래도 불확실 묶음에 포함합니다(확정 표본으로 분류하지 않음). 분석·화면 표시도 저장된 건수 값이 아니라 현재 묶음 구성으로 계산하므로, v0.5.1 이전에 저장된 오래된 표시도 저장 원본을 고치지 않고 올바르게 집계합니다(원본 표시는 다음 병합 때 정리).

- 각 결과는 **실행 당시 입력 스냅샷** 기준으로 화면·보고서에 표시합니다. 이후 입력이 바뀌면 ‘이전 결과 · 재분석 필요’를 표시하고, 거래를 모두 지워도 이전 결과는 깨지지 않고 그대로 보입니다.
- 자동 조회는 이미 입력한 본건 좌표·시군구·단지 거리·준공연도·사용자 제외 사유를 덮어쓰지 않습니다.

## 표시 원칙

- 금액은 내부에서 원으로 계산하고 만원으로 표시합니다. 면적은 전용㎡ 기준이며 1평=400/121㎡입니다.
- 숫자마다 분석 기준일·금액 단위·면적 기준·출처(가상/사용자 제공/공식 API)를 표시합니다.
- 관찰된 변화, 비교 차이, 미추정(인과효과)을 구분합니다. 적정가격·예상 상승률을 만들지 않습니다.
- 자료가 없으면 ‘보류’ 또는 ‘미산출’로 남깁니다. 0원으로 채우지 않고, 빈 기간을 가상 거래로 채우지 않습니다.
- 비교 가능한 단지가 5개보다 적으면 그만큼만 표시합니다.

| 저장 전 작업 | 브라우저 탭 세션 | 탭을 닫으면 사라짐 |
| 이 브라우저에 저장 | localStorage | 브라우저 데이터 삭제·다른 기기에서는 자동 복구 안 됨 → JSON 백업 권장. 저장소가 차단되거나 공간이 부족하면 ‘저장되지 않았습니다’ 오류와 JSON 내보내기 버튼을 표시(성공으로 처리하지 않음) |
| 저장소 손상 | localStorage | 원문을 해석할 수 없으면 빈 저장소로 취급하지 않고 쓰기 차단, ‘원문 내보내기’ 제공. ‘손상 원문 보관 후 새로 시작’은 사용자 실행으로만(원문을 보관 키에 복사·확인 후). 일부 기록만 손상이면 정상 기록은 사용하고, 저장 시 손상 기록 원문을 그대로 다시 씀(자동 삭제 없음) |
| 백업 복구 | localStorage | 같은 식별자의 기존 기록은 덮어쓰지 않음(같은 내용은 건너뛰고, 다른 내용은 ‘복구 사본’으로 추가) |
| 서버 영구 보관 | 없음 | 새 앱 로그인·자료별 권한·삭제·복구 정책 결정 후 활성화 예정 |

| 이름 | 기본값 | 설명 |

| `MOLIT_SERVICE_KEY` | 미설정 | 국토교통부 아파트 매매 실거래가(data.go.kr 15126469) — 실제 호출 미검증 |

| `PUBLIC_DATA_MAX_MONTHS` | 12 | 한 번에 조회하는 최대 개월 수(시군구 최대 6곳, 시군구·월당 최대 20쪽, 단지 좌표 최대 80곳) |

| `COOKIE_SECURE` | `true` | 운영 HTTPS에서 반드시 true |
